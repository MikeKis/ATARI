# ATARI — имитационное обучение импульсных нейронных сетей

Исследовательский проект: обучение импульсной нейронной сети (ИмНС) действиям агента
по показу учителя. Платформа — симулятор ArNI-X (`C:/SNN/ArNI`), сетевая архитектура —
варианты CoLaNET.

## Идея проекта

В базовой постановке имитационное обучение сводится к задаче классификации. Учитель
(алгоритм, уже хорошо решающий задачу, или человек) показывает обучающейся системе,
какие действия в каких состояниях внешнего мира надо делать, чтобы достичь цели.
Обучающаяся система должна построить набор бинарных классификаторов — по одному
на каждое элементарное действие:

    состояние мира (+ при необходимости его предыстория) -> сработать ли этому действию.

Спайк классификатора служит триггером своего действия. Пока ни один классификатор
не сработал, агент бездействует: молчание — это отсутствие команды, а не отдельный
класс. Если действия антагонистичны и не выполняются вместе, взаимно блокируются их
выходные нейроны: при одновременном срабатывании арбитр WTA оставляет одного
победителя.

Отличия от классической классификации изолированных объектов (например, MNIST в
Tutorial 3 документации ArNI-X):

- состояние мира меняется непрерывно; периодического сброса нейрона нет, соседние
  моменты времени связаны;
- агент решает, действовать ли, каждые `P` тактов. Для сети `P` — глубина сведений
  о мире, по которым принимается решение: спайк действия, после которого в пределах
  `P` тактов пришла та же команда учителя, уже верен; если спайка не было —
  форсированное обучение. Задержка дофаминовой связи 3 такта;
- положительная метка приходит только когда это действие нужно, и каждый
  классификатор решает независимо;
- метка редкая: большую часть времени классификатор должен молчать, поэтому
  качество считают по precision/recall действия, а не по доле верных тактов;
- качество модели измеряется ещё и результатом поведения агента, когда обученная
  сеть сама управляет объектом.

Ключевые механизмы обучения остаются теми же, что в CoLaNET:

- **форсированное обучение** — метка учителя форсирует спайк одного из нейронов
  «своей» колонки через BIASGATE и WTA-арбитраж;
- **дофаминовая пластичность** — метка потенциирует синапсы победителя;
- **анти-хеббовская пластичность** — нефорсированный спайк без последующей метки
  депрессирует участвовавшие синапсы.

Сигналы поощрения и наказания из окружения (предназначенные для обучения с
подкреплением) в имитационном обучении не используются для пластичности, но служат
метрикой поведения агента.

## Этапы (от простого к сложному)

1. **Ping-pong** (текущий этап) — учитель-алгоритм (`Actions::bGenerateSignals` в
   `ping-pong/environment/ping-pong-environment-rec.cpp`), состояние — дискретизированные
   координаты и скорость мяча плюс положение ракетки; два антагонистических
   действия — вверх и вниз, молчание обоих классификаторов оставляет ракетку на месте.
   Решения принимаются только когда мяч летит влево. Точка встречи на этом полёте не
   меняется, поэтому ракетка учителя изредка, примерно каждое десятое решение, смещается
   случайно: так за один полёт учитель показывает и движение вверх, и движение вниз, а
   следы старой и новой позиции почти не накладываются. Сложность игры регулируется
   скоростью и размером ракетки.
   Спека: `.specs/2026-10-13_ping-pong-imitation-learning.md`.
   Запуск — из `ping-pong/Workplace`: исполняемые файлы и DLL ArNI подключены
   символическими ссылками на `C:/SNN/ArNI/Workplace`, ничего из ArNI не копируется.
   Полный поиск гиперпараметров запускается на Linux (`Workplace/setup_links.sh`,
   затем SuperArNI против `Experiments/ImitationPingPong.inc`). Пороги F1 и доли
   отбитых мячей дописываются в спеку после этого прогона.
2. Далее (уточняется по результатам этапа 1): использование предыстории состояния,
   более сложные среды, учитель-человек, перенос обученной сети на нейрочип.

## Структура репозитория

- `ping-pong/environment/` — DLL окружения `ping-pong-environment` по протоколу ArNI-X:
  рецепторы (`Punishment`, `Reward`, состояние `R`, учитель `Actions`), readout
  (интерпретация выходных спайков как команд ракетке), модель мира (`UpdateWorld`).
- `ping-pong/ping-pong-visualizer/` — SFML-визуализатор, читающий состояние из
  разделяемой памяти `ping-pong-environment.sm`.
- `ping-pong/Experiments/` — конфигурации сетей (`.nnp`, `.nnc`), собранные DLL.
- `ping-pong/WorldModelTest/`, `ping-pong/*.py`, `ping-pong/Experiments/WorldDynamics.nnp` —
  более ранняя линия экспериментов (модель динамики мира на DyALA/Time), к имитационному
  обучению не относится.
- `pugixml-1.10/` — XML-парсер (vendored).
- `.specs/` — спецификации задач (spec-driven development).
