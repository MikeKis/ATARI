# Имитационное обучение CoLaNET в ping-pong (этап 1 проекта)

- **Дата**: 2026-10-13
- **Статус**: Draft
- **Связанные issue/PR**: нет. Общая идея проекта — `README.md` в корне репозитория.

## Цели

1. Окружение `ping-pong-environment` (DLL по протоколу ArNI-X) поддерживает режим
   имитационного обучения: учитель-алгоритм выдаёт метку того элементарного действия,
   которое нужно выполнить, управляет ракеткой в период обучения и теста, а выходные
   спайки сети используются для непрерывной оценки точности её решений.
2. Есть вариант CoLaNET для непрерывно меняющегося состояния, без периодического
   сброса нейронов: по входу `R` (108 рецепторов состояния) и меткам учителя `Actions`
   обучаются два независимых бинарных классификатора, `ActDown` и `ActUp`. Спайк
   выходного нейрона классификатора — триггер своего действия. Молчание обоих
   оставляет ракетку на месте.
3. Есть режим, в котором уже обученная сеть сама управляет ракеткой; качество
   измеряется долей отбитых мячей (`nRewardsTot / (nRewardsTot + nPunishmentsTot)`),
   процесс можно наблюдать в `ping-pong-visualizer`.
4. Сложность задачи регулируется параметрами запуска без пересборки: период команд
   (скорость ракетки), шаг ракетки за команду, размер ракетки.
5. Задача подготовлена к оптимизации гиперпараметров CoLaNET через ArNI_GA:
   `.inc`-файл с генами и `EVALUATOR`, fitness — код завершения `ArNIGPU`.
6. Измеримый результат этапа: на базовой сложности (`action_period` 15, шаг ракетки
   `1/30`, размер `0.18`) после первого полного прогона GA фиксируются пороги среднего
   F1 на тесте и доли отбитых мячей у агента. До этой фиксации прогон обязан выдавать
   обе метрики; успех этапа — превышение зафиксированных порогов. Доля отбитых мячей
   сравнивается с неподвижной ракеткой на той же сложности.

## Не цели

- Обучение с подкреплением: сигналы `Reward` / `Punishment` не участвуют в
  пластичности; они остаются только метрикой поведения.
- Отдельный модуль предыстории (`Time`, `DyALA`, `MultistatePredictor` из
  `ping-pong/Experiments/WorldDynamics.nnp`). Глубина `P` на этом этапе — окно следа
  самой колонки CoLaNET, а не дополнительная популяция.
- Изменение ядра ArNI (`ArNI`, `ArNICPU`, `ArNIGPU`) и шаблона
  `C:/SNN/ArNI/Experiments/CoLaNET.nnp`. Все изменения — в репозитории `ATARI`.
- Новый модуль `SpecialNetworkStructures/*`: сеть описывается декларативно в `.nnp`.
- Учитель-человек, другие среды, нейрочип.
- Сохранение/восстановление обученной сети между запусками (`.nns`): все фазы —
  в одном запуске эмулятора. `LoadStatus` в окружении остаётся как есть.
- Переработка более ранних артефактов (`WorldModelTest`, python-скрипты модели мира),
  кроме сохранения их работоспособности (п. «Совместимость»).
- Единый мультиклассовый классификатор, в котором «нет действия» — такой же класс,
  как вверх и вниз. На этом этапе каждое элементарное действие — свой бинарный триггер.

## Принятые решения

1. **Глубина `P`, без сброса.** Агент принимает решение каждые `P = action_period`
   тактов (такты `0, P, 2P, …`). Для сети это не цикл презентации объекта. `P` — глубина
   сведений о внешнем мире, по которым принимается решение о действии.
   - У популяции `L` нет узла `reset_period`. В ядре ноль означает «не сбрасывать»
     (`NeuLIF`: сброс выполняется только при ненулевом `ResetPeriod`). Потенциал и следы
     спайков сохраняются через границу решений: соседние состояния мира связаны.
   - Вход `R` идёт каждый такт.
   - Метка нужного действия испускается на самом такте решения. Фазы `P − 4` нет.
   - Если колонка действия уже спайкнула в окне `(t − P, t]` перед меткой на такте `t`,
     та же команда учителя пришла в пределах глубины — решение верное: анти-хеббовская
     депрессия этого спайка и дофамин компенсируют друг друга.
   - Если в этом окне спайка не было — форсированное обучение: метка форсирует
     `BIASGATE → L`, затем дофаминовая связь `Actions → L` с задержкой 3 приходит уже
     после форсированного спайка. Задержка 3 сохраняется.
   - `dopamine_plasticity_time = P + 3`, чтобы дофамин на такте `t + 3` ещё действовал
     на спайк из `(t − P, t]`. `maxTSSISI = P − 1`: спайки одной глубины образуют одну
     TSS, а спайки соседних решений (интервал ровно `P`) — нет.
   - `chartime` остаётся отдельным параметром нейрона и с `P` не отождествляется.
2. **Набор бинарных триггеров.** На каждое элементарное действие — своя колонка
   CoLaNET (`ActDown`, `ActUp`): форсирование и дофамин приходят только в ту колонку,
   чьё действие учитель выполнил на этом решении. Ложное срабатывание колонки без метки
   депрессируется анти-хеббовской пластичностью. Колонки не соревнуются за общий
   максимум голосов. Спайк `OUT` колонки — триггер своего действия; нет спайка — нет
   команды. На одном решении учитель испускает не больше одной метки.
3. **Взаимное подавление антагонистов на `OUT`.** Связаны нейроны `OUT` двух действий,
   не нейроны `L`. Внутри колонки `L` остаётся обычный WTA CoLaNET
   (`L → L`, `all-to-all-sections`): он выбирает один распознаватель подкласса и к
   другому действию не относится.
   - В блоке `<!--MUTUAL_SUPPRESSION-->` — gating `OUT → OUT`, `policy="all-to-all"`,
     вес `-P`. Связь лежит внутри копируемого `NETWORK`, поэтому пара `OUT` каждой копии
     блокирует сама себя, а копии друг друга нет. `NetworkSingleton::Optimize` собирает
     такую пару в абсолютную WTA-секцию из 2 нейронов и снимает эти gating-синапсы
     (`ArNI/Optimize.cpp`). Проигравший неактивен `P` тактов (`InactivationTime = P`).
   - Если оба `OUT` пересекли порог на одном такте, взаимной блокировки спайком нет:
     арбитр WTA выбирает одного победителя. Ключ сравнения — превышение потенциала над
     порогом в старших битах и случайные биты `X` в младших (`NeuLIF::btact`).
     Стохастическая стимуляция делает выбор случайным. Спайк победителя выходит на
     следующем такте.
   - Readout применяет действие этого победителя. Отмены обеих команд нет.
   - Блок в базовой конфигурации включён. В логе старта на каждую копию есть строка
     `Optmizing absolute WTA section with 2 neurons`.
4. **Решение каждые `P` тактов и только на полёте влево.** Кандидаты в решения — такты
   `0, P, 2P, …`. Команда вычисляется лишь если `vx < 0` (мяч летит к ракетке). При
   `vx ≥ 0` такт пропускается: метки нет, ракетка не двигается, пример в F1 не входит.
   Полёт вправо в обучение не берётся: до левой стенки траектория может много раз
   отразиться, и по текущему состоянию сеть эту связь не выучит. На левом полёте команда
   бывает и нулевой. Текущий `Actions::CommandCooldown` удаляется. Триггер классификатора
   на решении `t` — спайкнул ли его `OUT` хотя бы раз в `(t − P, t]` у большинства копий
   ансамбля. На первом решении окно пусто.
5. **Фазы одного запуска.**
   - `[0, learning_time)` — обучение: учитель управляет ракеткой, метки испускаются,
     пластичность включена. На каждом `log_period` в лог пишется F1 классификаторов
     по скользящему окну — кривая обучения. Эти числа только для наблюдения: в fitness
     они не входят, пластичность и управление ракеткой от них не зависят;
   - `[learning_time, agent_start_time)` — тест классификации: учитель управляет
     ракеткой, метки **не** испускаются, пластичность выключена опцией эмулятора
     `-f<learning_time>` (иначе анти-хеббовская пластичность без дофамина разрушит веса);
     здесь считается F1 триггеров, и он же идёт в fitness;
   - `[agent_start_time, T)` — агент: ракеткой управляет сеть, считаются отбитые и
     пропущенные мячи.
   Любая фаза может быть пустой (например, `agent_start_time = learning_time`
   даёт чистый режим агента после обучения).
6. **Единая точка движения ракетки.** В обоих режимах команда применяется в readout на
   такте решения (источник — глобальная переменная с командой учителя или триггеры сети
   по окну `(t − P, t]`). При одинаковых командах на одних и тех же тактах траектории
   совпадают побитно — это используется в приёмочных тестах.
7. **Fitness.** `Finalize` возвращает `10000 × метрика`, метрика выбирается параметром:
   средний F1 двух бинарных триггеров на тестовой фазе или доля отбитых мячей в фазе
   агента. Доля верных решений в fitness не входит: отрицательный класс (молчание)
   доминирует.
8. **Сеть — самостоятельный `.nnp`** в `ping-pong/Experiments/`, секции CoLaNET
   описаны явно (не через `\CoLaNET`). Имена макросов пластичности совпадают с
   `C:/SNN/ArNI/Experiments/CoLaNET.nnp` и `C:/SNN/ArNI/tests/MNIST.inc`. Узел
   `reset_period` не копируется. `dopamine_plasticity_time` и `maxTSSISI` задаются
   от `P` (решение 1).
9. **Редкие случайные смещения ракетки в фазах учителя.** Пока мяч летит влево, величина
   скорости постоянна, и `rTargetYAtLeftWall` даёт одну точку встречи. Учитель без
   возмущения повторяет команду одного знака, а после входа в порог молчит. Смещение
   прибавляется не на каждом решении, а на каждом `jitter_every`-м решении левого полёта
   (базовое значение `10`), после команды учителя: равномерный сдвиг из
   `[-racket_jitter, racket_jitter]`, затем ограничение площадкой. Базовое
   `racket_jitter = 0.25`. Интервал в `10` решений — это `10·P` тактов, много больше
   `chartime` и дофаминового окна `P + 3`, поэтому след спайков от старой позиции ракетки
   редко налезает на новую. На один полёт влево приходится порядка десятка таких смен.
   Между смещениями учитель ведёт ракетку к той же точке обычными командами. В фазе
   агента смещения нет. `racket_jitter = 0` смещение выключает. Сдвиг берётся из `rng`,
   при фиксированном seed прогон воспроизводим. Траекторию мяча этот механизм не меняет.
10. **Базовая сложность фиксирована.** `action_period = 15`: шаг ракетки `1/30` происходит
    раз в 15 тактов (`1/450` поля за такт), дофаминовое окно — `18` тактов. Шаг ракетки
    `1/30`, размер `0.18`, диапазон скорости мяча (`minSpotPassageTime_ms`,
    `maxSpotPassageTime_ms`), `racket_jitter = 0.25` и `jitter_every = 10` тоже не
    входят в пространство GA. Иначе отбор сдвигает сложность к самой лёгкой задаче.
    Гены — только параметры сети CoLaNET.
11. **Длительности полного прогона.** Как в MNIST: 60000 интервалов обучения, 10000 теста,
    10000 агента, каждый интервал длиной `P` тактов. Границы фаз: `learning_time = 900000`,
    конец теста `1050000`, конец агента `1200000`. Пример для F1 — только такт сетки с
    `vx < 0`, поэтому обучающих примеров меньше 60000. `#define SMOKE_GA` эти квоты сокращает.
12. **Символические ссылки на ArNI, без копий.** Запуск из `ping-pong/Workplace`.
    `ArNIGPU.exe`, `ArNI_GA.exe` и DLL модулей ArNI, которые эмулятор грузит из каталога
    exe, — символические ссылки на файлы в `C:/SNN/ArNI/Workplace`. Собственная
    `ping-pong-environment.dll` собирается в `ping-pong/Experiments` и в `Workplace`
    попадает ссылкой. `ArNI_OPT.inc`, который читает SuperArNI и ArNI_GA, — ссылка на
    `ping-pong/Experiments/ImitationPingPong.inc`. Копий этих файлов нет. Так делается
    всегда: нужный файл ArNI подключается ссылкой, а не копией.

## Как устроено сейчас

Факты по коду `ping-pong/environment/`.

- Поле `[-0.5, 0.5]²`; ракетка у левой стенки `x = -0.5`, размер `RACKET_SIZE = 0.18`
  (макрос в `ping-pong/ping-pong-environment.h`, используется окружением и
  визуализатором). Скорость мяча — от `1/700` до `1/200` поля за такт
  (`rMakeBallVelocity`).
- `rec_ping_pong` (108 рецепторов `R`): `nSpatialZones = 30` зон по `x`, `y`, `ry` и
  `nVelocityZones = 9` зон по `vx`, `vy`; активный рецептор зоны спайкует с вероятностью
  `rStateFiringFrequency = 0.9` каждый такт. Вызывает `UpdateWorld` и безусловно пишет
  `ping_pong_state.csv`, `ping_pong_state_discrete.csv`.
- `Evaluator` (`Punishment`, `Reward`): спайк при пропуске / отбитии мяча; после него
  вход `R` блокируется на `afterRewardSilence = 30` тактов (`InputBlockCounter`).
- `Actions` (2 рецептора `ActDown`, `ActUp`): цель — `rTargetYAtLeftWall()`
  (прогноз `y` мяча у левой стенки с отражениями), команда, если
  `|target − racket| > 0.5 / nSpatialZones`; не чаще `action_period` тактов
  (`CommandCooldown`, отсчёт от последней команды, а не от сетки тактов). Ракетку
  **не** двигает. На одном полёте величина скорости мяча постоянна, поэтому точка
  встречи не меняется и команды учителя одного знака, пока ракетка к ней не придёт.
- Readout (`ping-pong-environment-rea.cpp`): `nNeuronsperAction = nOutputNeurons / 2`;
  каждый спайк выходного нейрона сдвигает ракетку на `1 / nSpatialZones`; печатает
  `rew/pun` каждые 200000 тактов; `Finalize` возвращает `nRewardsTot·10000 / (rew+pun)`,
  считая с `start_time`.
- Порядок создания рецепторов в `RECEPTORS_SET_PARAMETERS` фиксирован номером вызова:
  `Punishment`, `Reward`, `R`, `Actions`.
- Разделяемая память `ping-pong-environment.sm`: `pair<pair<float,float>,float>` =
  `(x, y)` мяча и `y` ракетки; создаёт визуализатор, окружение подключается, если она есть.
- `C:/SNN/ArNI/Experiments/CoLaNET.nnp`: колонки `L` (`NLEARNINGGROUPS × NTARGETCLASSES`),
  `OUT`, `BIASGATE`; `$(REWARD) → L` (reward, delay 3, aligned), `$(REWARD) → BIASGATE`
  (forcing, aligned), `BIASGATE → L` (forcing), `L → OUT`, `OUT ⊣ BIASGATE`,
  `L ⊣ L` внутри колонки; `reset_period = $(PRESENTATION_PERIOD)`.

## Функциональные требования

### Окружение: рецептор `Actions` (учитель)

1. Параметры в `args` (через `GetAllParameters`, имена lower case):
   - `action_period` — интервал решений `P` (такты), ≥ 4; обязателен;
   - `learning_time` — метки испускаются только при `ntact < learning_time`;
     `0` — всегда (текущее поведение);
   - `racket_step` — сдвиг ракетки за одну команду в долях поля, по умолчанию
     `1 / nSpatialZones`;
   - `racket_size` — размер ракетки, по умолчанию `0.18`;
   - `movement_threshold` — порог `|target − racket|`, по умолчанию `0.5 / nSpatialZones`.
2. На каждом такте `ntact`, кратном `P`, при `vx < 0` учитель вычисляет команду `Down`,
   `Up` или молчание и сохраняет её в глобальную переменную. При `vx ≥ 0` команда —
   молчание, спайка нет. При `ntact < learning_time` и ненулевой команде на том же такте
   спайкует один рецептор, `ActDown` или `ActUp`. Оба рецептора на одном решении не
   спайкуют. На тактах между решениями спайков нет.
3. `GetMeanings`: `ActDown`, `ActUp`. Рецепторов два, как в текущем `Actions`.
4. `SaveStatus` / `LoadStatus` сохраняют новые поля.

### Окружение: рецептор `R` и `Evaluator`

5. `after_reward_silence` (в `args` рецептора `R`) — длина блокировки входа после
   поощрения/наказания; по умолчанию `30` (как сейчас); в имитационной конфигурации `0`.
6. `dump_state` (узел-флаг в `args` рецептора `R`) включает запись
   `ping_pong_state*.csv`; без флага файлы не пишутся. Это изменение умолчания:
   скрипты модели мира, которым нужны CSV, должны добавлять флаг.
7. Поведение `Evaluator` не меняется, кроме того, что блокировка входа применяется
   только при `after_reward_silence > 0`.

### Окружение: readout

8. Параметры в `args` узла `Readout`:
   - `start_time` — начало тестовой фазы (как сейчас; обычно равен `learning_time`);
   - `agent_start_time` — начало фазы агента; по умолчанию — конец эмуляции (фазы
     агента нет);
   - `fitness` — `f1` (средний F1 двух триггеров на тестовой фазе, по умолчанию)
     или `hits` (доля отбитых мячей в фазе агента);
   - `log_period` — период печати текущих метрик в тактах, по умолчанию `200000`;
   - `report_file` — путь CSV-отчёта (по действию: TP, FP, FN, TN, precision, recall, F1);
     без параметра отчёт не пишется;
   - `window` — ширина скользящего окна текущего F1 в решениях, по умолчанию `1000`;
   - `racket_jitter` — амплитуда случайного сдвига ракетки после команды учителя
     (решение 9); по умолчанию `0`;
   - `jitter_every` — сдвиг на каждом таком по счёту решении левого полёта; по умолчанию
     `10`; значение меньше `1` — ошибка конфигурации.
9. Число выходных нейронов должно делиться на число действий `K = 2`. Раскладка секции
   `OUT` при `ncopies` / `merge="yes"` — копия за копией, внутри копии действия по
   порядку рецепторов `Actions`, как чанки в `ObjectClassifier`: нейрон
   `copy * K + a` принадлежит действию `a`. Иначе — ошибка конфигурации с сообщением.
10. На такте решения `t` при `vx < 0` по каждому действию считается, в скольких копиях его
    `OUT` спайкнул хотя бы раз в `(t − P, t]`. Триггер срабатывает, если таких копий
    больше половины ансамбля (при одной копии — если был хотя бы один спайк). При
    `vx ≥ 0` триггер не вычисляется.
11. На такте решения при `vx < 0` применяется команда к ракетке: в фазах учителя —
    команда учителя (молчание — без шага команды), в фазе агента — действие победителя
    WTA (решение 3). Если в окне остались спайки обоих действий (разные копии ансамбля),
    берётся действие с большим числом сработавших копий; при равенстве шага команды нет.
    Сдвиг `JitterRacket` — только в фазах учителя, только при `vx < 0` и
    `racket_jitter > 0`, и только на каждом `jitter_every`-м таком решении: равномерное
    смещение из `[-racket_jitter, racket_jitter]` и ограничение площадкой (решение 9).
    Метка этого такта уже выдана по положению до сдвига. При `vx ≥ 0` и между решениями
    ракетка не двигается.
    Применение — одна функция `ApplyRacketCommand`, ограничение
    `[-0.5 + size/2, 0.5 − size/2]`. Текущая логика «спайк = сдвиг» удаляется.
12. Метрики, отдельно по каждому действию, только по решениям с `vx < 0`. Сравнение одно
    и то же в обучении и в тесте: команда учителя на решении `t` против триггера в
    `(t − P, t]`.
    - TP — учитель дал метку и триггер сработал; FP — метки не было, триггер сработал;
      FN — метка была, триггер молчал; TN — оба молчали;
    - с периодом `log_period`, и в обучении, и в тесте: в консоль — F1 скользящего окна
      по каждому действию, средний F1 и `rew/pun`. Если задан `report_file`, туда же
      дописывается строка кривой (`tact`, фаза, F1 по действиям, средний F1);
    - в `Finalize`: по тестовой фазе — счётчики, precision, recall, F1 по действиям,
      средний F1, число решений со спайками обоих действий, `rew/pun` фазы агента.
      F1 фазы обучения в код завершения не входит (решение 5).
13. Остановка по `100000` тактам без движения ракетки сохраняется только для фазы
    агента. В фазах учителя ракетка стоит между решениями, на полёте вправо и на тех
    решениях влево, которые не попали на `jitter_every`.
14. `Finalize` возвращает `10000 × метрика` по `fitness`; при пустой соответствующей
    фазе — `1` (как `ObjectClassifier` при отсутствии теста).

### Разделяемая память и визуализатор

    { float x, y, racket_y, racket_size; }` в `ping-pong/ping-pong-environment.h`.

## Нефункциональные требования

- Производительность: накладные расходы readout и учителя — O(число выходных спайков)
  за такт, без аллокаций в горячем пути; CSV состояния по умолчанию выключен.
- Память: четыре счётчика на действие и скользящее окно фиксированного размера;
  история решений не хранится. Для окна `(t − P, t]` достаточно отметок «копия уже
  спайкнула в текущем окне», сбрасываемых на такте решения.
- Потокобезопасность: как сейчас — рецепторы и readout вызываются эмулятором
  последовательно; общие глобальные переменные DLL без блокировок.
- Совместимость:
  - экспорты DLL (`SetParametersIn`, `LoadStatus`, `SetParametersOut`,
    `ObtainOutputSpikes`, `Finalize`, `Serialize`, `GetSections`, `ObtainSpikes`)
    не меняются;
  - `WorldDynamics.nnp` и производные `.nnc` загружаются с новой DLL без правок
    (`Actions n="2"`, `after_reward_silence = 30`), кроме необходимости флага
    `dump_state` для получения CSV;
  - разделяемая память: новая раскладка, визуализатор и окружение обновляются вместе;
  - Windows: `ping-pong.sln`, Release|x64 (Debug — по возможности); Linux: `CMakeLists.txt`
    с новыми файлами;
  - каталог exe — `ping-pong/Workplace`; файлы ArNI и `ping-pong-environment.dll` в нём
    являются символическими ссылками (решение 12), не копиями. `LoadLibrary` ищет DLL
    в каталоге exe.
- Наблюдаемость: кривая обучения — те же строки F1 в консоль и в `report_file` с периода
  `log_period` уже в фазе обучения; итоговые счётчики теста — в `Finalize`. Понятные
  сообщения об ошибках конфигурации (какой параметр и почему).

## Критерии приёмки

### Автотесты

Фреймворка автотестов в репозитории нет; приёмка — скрипт `ping-pong/tests/run_imitation_smoke.bat`
с проверкой кодов возврата `ArNIGPU` и содержимого отчётов. Все прогоны — с фиксированным
seed (без `-R`).

- [ ] **Разнообразие меток на полёте влево**: учитель управляет ракеткой,
  `racket_jitter = 0.25`, `jitter_every = 10`. Пока `vx < 0`, в логе меток есть и
  `ActDown`, и `ActUp`, а число сдвигов ракетки примерно в `10` раз меньше числа решений
  этого полёта. Пока `vx ≥ 0`, меток нет и `y` ракетки постоянен. При `racket_jitter = 0`
  на одном полёте влево встречается не больше одного из двух рецепторов.
- [ ] **Эхо учителя, режим учителя**: `teacher-echo.nnc`, `fitness = f1`,
  `racket_jitter = 0`, `start_time = 0`, `learning_time = 0` (метки на каждом решении
  влево). Форсирующий спайк `OUT` приходит после метки, поэтому в окно `(t − P, t]` этого
  же решения он не попадает и даёт FN. В `report_file` у обоих действий FP = 0. Ракетка
  двигается только на тактах, кратных `P`, и только при `vx < 0`.
- [ ] **Эхо учителя, режим агента**: тот же `.nnc`, `agent_start_time = 0`,
  `dump_state`. Спайк `OUT` на такте `t + d` (`d` — задержка форсирующей связи) попадает
  в окно следующего решения. Положение ракетки в прогоне агента на такте `n + P`
  совпадает с положением в прогоне учителя на такте `n` (один и тот же seed); `rew/pun`
  после выравнивания на `P` совпадают.
- [ ] **Ошибки конфигурации**: `nOutputNeurons` не кратно 2; `action_period < 4` —
  эмуляция не стартует, сообщение называет параметр.
- [ ] **Базовая конфигурация**: `ImitationPingPong.nnc` не содержит `reset_period`,
  содержит `dopamine_plasticity_time`, равный `action_period + 3`, и gating `OUT → OUT`
  (`all-to-all`, вес `-action_period`).
  `NLEARNINGGROUPS` базовой конфигурации не равен 2, поэтому строки лога
  `Optmizing absolute WTA section with 2 neurons` — это пары `OUT`, и их число равно
  числу копий. На укороченных фазах (`SMOKE`: 3000 / 1000 / 1000 решений)
  прогон завершается с кодом в `[0, 10000]`; в консоли есть строки F1 по действиям
  ещё до `learning_time`; `report_file` содержит точки кривой обучения и итоговые
  TP/FP/FN/TN для `ActDown` и `ActUp`.
- [ ] **Совместимость**: `.nnc`, полученный из `WorldDynamics.nnp` с подстановкой макросов,
  загружается новой DLL (рецептор `Actions` с двумя выходами, вход блокируется после
  поощрения); с флагом `dump_state` появляются оба CSV.
- [ ] **Визуализатор**: при `racket_size = 0.3` в `.nnc` ракетка в окне визуализатора
  рисуется размером `0.3 × RASTER_SIZE` пикселей.
- [ ] **GA-смок**: `ArNI_GA` с `ImitationPingPong.inc` (`SMOKE_GA`, `-p8 -M2`)
  проходит два поколения без `Selection criterion fails - all values are equal`.
